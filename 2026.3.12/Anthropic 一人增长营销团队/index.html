    Anthropic营销团队

    标题：Anthropic 靠一个人做增长营销？营销人必看AI实操方法

    刚刚外网冲浪看到一条帖子，营销人表示有被冲击到（对AI代替人有了实感）。

    Anthropic 的市场部，去年有10个月时间，做增长营销的只有一个人。

    熟悉大模型市场的人都知道，去年 Anthropic 可以说增速惊人，年化收入从年初的10亿美元，一路飙涨到年底的90亿美元（最新数据，已经涨到190亿美元了...）。

    这位"一人团队"的当事人叫 Austin Lau，负责效果营销。

    换句话说，Anthropic 公司业务涉及到的所有社媒、搜索平台投放、应用商店优化、电子邮件营销和SEO，都由他来做。

    准确一点，是他跟 Claude Code。

    印象最深刻的是，Austin 本人没有一点技术背景，最初甚至连终端是什么都不知道，工作过程中也没写过一行代码。

    而他借助 Claude Code，把自己重复性的工作流自动化，最终实现了10倍的产出，广告制作时间从2小时缩短到15分钟。

    鉴于最近我也在深度使用 Claude Code，对这个数字我还是比较相信的。

    而且我发现早在1月底，Anthropic 就在一份报告里，公开了怎么做增长营销的方法，基本上就是来自于 Austin 的实操经验。

    报告写得很具体，看多了一人公司的神话，这种实操方法真是难得。

    BTW，Austin 已经出来认领了这条帖子，表示将在之后分享更多 knowhow（感兴趣的可以关注他的推特账号 @helloitsaustin）。

    下面是我看完那份报告，记录下来的核心工作流，以及一些思考。

    过谷歌广告投放的都知道，写文案是一件费脑子的体力活。

    1. Google Ads 文案创意生成 做过谷歌广告投放的都知道，写文案是一件费脑子的体力活。

    需要产出的内容成千上百条，而且标题跟描述的字符限制还很严格，写法也不一样。

    Austin 的做法是在 Claude Code 里建一个自定义斜杠命令，触发之后输入投放数据、现有文案和关键词，Claude Code 会交叉引用他事先设定好的品牌调性、产品规范和 Google Ads RSA 最佳实践，自动分析哪些广告在拖后腿，生成新的文案来替换。

    这背后有两个专门的 sub-agent（子代理），一个只写标题（≤30字符），一个只写描述（≤90字符）。

    每个agent 只专注一件事，产出质量远高于一个单独的 prompt。

    接着 Claude Code 会把生成的标题和描述打包成一个可以直接上传到 Google Ads 的 CSV 文件。

    流程最后，Austin 会作为审判员出现，看看生成的文案价值主张到不到位、语气对不对、跟竞品有没有区分度。

    2. Figma 插件批量出图

    文案有了，但广告投放不只是文字，还需要视觉素材——Facebook、Google、App Store，问题是每个渠道的广告尺寸和格式都不一样。

    数百条文案变体，现在要把它们分别塞进不同渠道、不同尺寸的视觉模板里。这个排列组合的工作量非常大，而且极其机械——复制粘贴、调位置、换尺寸、再导出，反反复复。

    Austin 的做法是用 Claude Code 开发一个 Figma 插件。

    具体的实现方式是，他在 Figma 里把所有广告模板按命名规则组织好（比如按渠道、按尺寸分别命名），插件启动后会自动识别这些模板 frame，然后把对应的文案变体批量填充进去。

    半秒钟处理一批，每批最多生成100个可以直接发布的广告变体。

    原来可能花一整个下午的事，现在一个按钮搞定。

    3. 直接在 Claude 里查投放效果 广告上线了，接下来的问题就是：哪条广告在赚钱，哪条在烧钱？

    Austin 自建了一个 MCP server（可以理解为一个让 Claude 直接跟外部工具对话的接口），接上了 Meta Ads API。

    这意味着他可以直接在 Claude 桌面端问："这周哪条广告转化率最高？""我在哪个渠道浪费了预算？"

    不用打开 Meta 广告后台，不用手动拉报表，实时数据直接出来。

    对于做效果营销的人来说，减少平台切换可能听起来是小事。

    但当你同时管着付费搜索、付费社交、App Store、邮件这么多渠道的时候，每天光在各个后台之间切来切去就已经是一种消耗了。

    决策链路越短，响应速度就越快。

    4. 系统自动迭代，越跑越聪明 最后也是我觉得最厉害的一环：他搭了一套 Memory 系统。

    每次广告实验的假设、变量、结果，都会被自动记录下来。下一轮生成新广告的时候，Claude 会自动调用之前所有实验的历史数据，知道什么方向有效、什么方向踩过坑。

    这就形成了一个闭环——生成、投放、分析、学习、再生成。而且系统会随着数据积累越来越聪明。

    上百条广告、跨好几个渠道的实验记录，换成人工来追踪是什么概念？可能需要一个专门的数据分析师才盯得过来。

    而 Austin 一个人，靠这套系统就跑起来了。

    说完 Austin 的具体做法，再聊聊更通用的东西。

    看完这个案例你可能会想，我又不做广告投放，这跟我有什么关系？

    其实核心逻辑是通用的：找到你工作里重复性的环节，用 AI 把它自动化。

    第一步：找到重复性工作

    去翻一翻你每天花时间最多、但最不需要动脑子的环节。

    不要低估自己工作的重复性。很多时候我们习惯了一套手动流程，就觉得"这就是工作本身"，其实那里面有大量可以被自动化的部分。

    也不一定是工作。比如我最近在求职，需要用一个表格实时跟踪投递的岗位和进度，发现"填表格"这个动作本身就是可以自动化的。

    第二步：把复杂流程拆开，逐步自动化 Austin 最值得学习的一点，就是他没有试图用一套万能方案解决所有问题，而是把工作流拆成了四个独立的模块，每个模块各自解决一个环节。

    这个思路很重要。如果你的工作流本身是复杂的，但你设计的自动化系统太简单（比如只用一个 prompt 试图搞定所有事），AI 产出的效果大概率不会好。

    应该先拆步骤，再逐个判断哪些环节可以自动化，然后针对每个环节去设计。

    一开始想不清楚也完全正常，可以跟 AI 交互着来，不断迭代。Austin 自己也说了，他搭的80%的东西最后都没用上，但这个过程帮他搞清楚了什么有效、什么没用。

    回到 Austin 身上。

    他能做到这些，本质上是因为他有营销的 knowhow——他知道广告投放的哪些环节是重复的、哪些指标值得盯、自动化之后应该测什么。

    工具只是杠杆，knowhow 才是支点。

    所以在 AI 时代，我觉得人更要去寻找自己的长处，知道自己的 knowhow 在哪。

    这样 AI 才能成为真正成为你的杠杆。
